# EcoInventery

Clean inventory and sales management web app for sellers — product catalog
with shelf-life tracking, QR code labels, supplier records, order history, and
stock insights for expiring and slow-moving items.

## Stack

- **Backend**: Node.js + Express, plain SQL (no ORM)
- **Database**: SQLite by default (zero setup), PostgreSQL optional
- **Auth**: bcrypt password hashing, JWT session in an httpOnly cookie
- **Frontend**: multi-page vanilla HTML/CSS/JS served from `/public`, no build step

## Run the demo

Requires Node.js 20 or newer. From the repository folder, install the locked
dependencies and start the server:

```bash
npm ci
npm start
```

The server listens on port `3000`; open the CodeSandbox preview or visit
`http://localhost:3000` when running locally. No `.env` file is needed for the
development demo. The repository includes a sanitized SQLite demo database at
`data/ecoinventory.db`, with sample products and sales. Startup adds the
supporting supplier, order, stock-history, and per-seller settings tables
without replacing existing inventory. If the database has no products, the
server seeds its sample inventory on startup.

The demo login is:

- Email: `seller@ecoinventery.com`
- Password: `demo1234`

When no `JWT_SECRET` is set in development, the server creates a random secret
in the gitignored `data/.jwt-secret` file. This lets demo sessions survive a
server restart in the same workspace. A fresh sandbox workspace creates its own
secret, so sign in there once. Never commit a real `.env` file or production
secret.

## Production configuration

Set `NODE_ENV=production` and provide a unique `JWT_SECRET` through the hosting
platform's secret settings. Generate a value with:

```bash
node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"
```

Put the result in the host's secret named `JWT_SECRET`. Set `BASE_URL` to the
public site address if QR codes are generated by a production deployment. In
development, QR codes use the address of the current request, which supports
CodeSandbox previews.

For PostgreSQL instead of SQLite, create a database, apply `schema.sql`, and
set `DATABASE_TYPE=postgres` plus `DATABASE_URL` (or the individual `PG_*`
variables) in the host environment.

## Environment variables

| Variable | Required | Default | Purpose |
|---|---|---|---|
| `PORT` | no | `3000` | HTTP port |
| `NODE_ENV` | no | `development` | `production` enables `Secure` cookies and requires a configured JWT secret |
| `DATABASE_TYPE` | no | `sqlite` | `sqlite` or `postgres` |
| `DATABASE_URL` | only for Postgres URL form | — | PostgreSQL connection string (overrides `PG_*`) |
| `PG_HOST` / `PG_PORT` / `PG_DATABASE` / `PG_USER` / `PG_PASSWORD` | only for Postgres var form | see `.env.example` | Individual PostgreSQL settings |
| `JWT_SECRET` | yes in production | random secret saved in gitignored `data/.jwt-secret` during development | Secret used to sign session JWTs |
| `BASE_URL` | no | current request address | Public URL encoded into product QR codes |

## API overview

| Method & path | Auth | Purpose |
|---|---|---|
| `POST /api/auth/register` | — | Create seller account (sets httpOnly JWT cookie) |
| `POST /api/auth/login` | — | Sign in |
| `POST /api/auth/logout` | — | Clear session cookie |
| `GET /api/auth/me` | ✓ | Current seller profile |
| `POST /api/products` | ✓ | Create product (validates `expiry_date > mfg_date`) |
| `GET /api/products` | ✓ | List the signed-in seller's products |
| `PUT /api/products/:id` | ✓ | Update product (partial) |
| `DELETE /api/products/:id` | ✓ | Delete product |
| `POST /api/products/:id/generate-qr` | ✓ | Generate QR PNG for the public page |
| `GET /api/insights` | ✓ | Expiring-soon (`?days=N`) & underperforming (`?threshold=X`) lists |
| `GET /api/suppliers` | ✓ | List the seller's suppliers and linked stock totals |
| `POST /api/suppliers` | ✓ | Add a supplier |
| `PUT /api/suppliers/:id` | ✓ | Update a supplier |
| `DELETE /api/suppliers/:id` | ✓ | Remove a supplier (linked products are kept) |
| `GET /api/orders` | ✓ | List orders (`?type=sale` or `?type=purchase`) |
| `POST /api/orders` | ✓ | Record an order and update stock in one transaction |
| `GET/POST /api/dashboard/settings` | ✓ | Read or save per-seller display settings |
| `POST /api/ai/forecast` | ✓ | Local stock and recent-sales estimates |
| `POST /api/ai/query` | ✓ | Local inventory summary answers |

The inventory copilot uses local rules and does not call an external AI model.

Scanning a QR code opens `GET /p/{slug}` — a public, no-auth, mobile-friendly
product page.
